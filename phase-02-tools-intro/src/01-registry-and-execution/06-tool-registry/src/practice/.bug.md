Practice folder bug fixes

Summary of changes made:

- meta.respone.ts
  - Fixed the `metaData` function which previously did not return an object and contained invalid syntax.
  - Made `requestId` generation safe (fallback when `crypto.randomUUID` is not available).
  - Returned a properly shaped `meta` object with `executionTimeMs`, `timestamps`, `requestId`, `agent`, and `toolDetails`.
  - Fixed typos like `WeatherAgnet` -> `WeatherAgent` and guarded access to `getWatherTool` properties.

- types.ts
  - Relaxed/aligned `StandaradrizationToolResponse` to match actual tool return shapes used in `tools.ts` (tools return `meta` and optional `error`).
  - Made `error` optional and flexible.
  - Accepted both `meta` and `metaData` keys so existing tool implementations don't break TS checks.

- version.check.ts
  - Corrected semantic version parsing and comparison logic (fixed typos and wrong boolean logic).
  - Properly compares major -> minor -> patch.

- registry.tools.ts
  - Avoided name collision between the class method `importFromJSON` and the imported function by aliasing the import to `importRegistryFromJSON` and using that inside the method.

Why these fixes were necessary:

- The `metaData` function had invalid JS and prevented consistent metadata being returned by tools.
- Type mismatches caused TypeScript to complain and prevented smooth integration between tool implementations and the `ToolType` signature.
- The version comparison had logical bugs that could allow outdated tools to overwrite newer ones.
- The import name collision risk could cause runtime or clarity problems when rehydrating tools from JSON.
