Tool-specific bugs and fixes

Discovered issues and resolutions:

1. registry.list used incorrectly in tests

- Issue: `test.ts` used `registry.list.length` which returns the function's `length` (number of parameters) instead of the array length.
- Fix: Use `registry.list().length` to get the number of registered tools. Updated `runtool/index.ts` to demonstrate correct usage.

2. Circular import between `meta.respone.ts` and `tools.ts`

- Issue: `meta.respone.ts` imported `getWatherTool` from `tools.ts` while `tools.ts` imported `metaData` from `meta.respone.ts` — caused circular dependency and incorrect runtime values.
- Fix: Removed the import from `meta.respone.ts`. `metaData` now accepts an optional `toolDetails` parameter. Updated `tools.ts` to pass tool details when calling `metaData`.

3. Semantic version comparison bug

- Issue: `version.check.ts` had typos and incorrect boolean logic, allowing an older/newer version mismatch.
- Fix: Implemented proper major->minor->patch comparison and robust parsing with fallbacks.

4. Import name collision in `registry.tools.ts`

- Issue: The helper function `importFromJSON` from `presistence.ts` collided with the class method `importFromJSON`.
- Fix: Aliased the imported function to `importRegistryFromJSON` and used it within the class method.

5. Response type mismatches

- Issue: The TypeScript `StandaradrizationToolResponse` expected rigid keys like `metaData` and a non-null `error`, whereas tools emitted `meta` and sometimes omitted `error`.
- Fix: Relaxed/expanded the interface to accept optional `error`, `meta` or `metaData` keys to better match implementations.
